# Проектирование и реализация микрофронтендов

## Уровень 1: Проектирование

### Выбор фреймворка
Для создания микрофронтендов я выбрал **Module Federation** — плагин Webpack, позволяющий совместно использовать модули (включая React-компоненты) между различными проектами.  
Этот подход обеспечивает:

- **Изоляцию**: Каждый микрофронтенд является независимым приложением, что позволяет разрабатывать и обновлять их отдельно друг от друга.
- **Динамическое связывание**: Компоненты и модули подгружаются только тогда, когда это необходимо, что снижает общий размер бандлов.
- **Удобное объединение**: Host-приложение (контейнер) управляет маршрутизацией и объединяет все микрофронтенды.

### Архитектура микрофронтендов
Проект состоит из следующих микрофронтендов:

1. **Auth**
    - Отвечает за авторизацию и регистрацию пользователей.
    - Логика: `login`, `register`
    - UI: формы регистрации и входа.

2. **Cards**
    - Управляет карточками (например, добавление, удаление, лайки).
    - Логика: работа с API карточек.
    - UI: отображение списка карточек.

3. **Profile**
    - Управляет профилем пользователя (информация и аватар).
    - Логика: запросы на изменение данных пользователя.
    - UI: форма редактирования профиля.

4. **Host**
    - Контейнерное приложение, которое объединяет микрофронтенды.
    - Управляет маршрутизацией между микрофронтендами.

## Уровень 2: Планирование изменений

### Структура проекта
Каждый микрофронтенд будет иметь следующую структуру:

```plaintext
frontend/
├── microfrontend/
│   ├── auth/
│   │   ├── src/
│   │   │   ├── components/       # UI-компоненты (например, LoginForm, RegisterForm)
│   │   │   ├── utils/            # Логика работы с API (auth.js)
│   │   │   └── App.jsx           # Точка входа микрофронтенда Auth
│   │   ├── webpack.config.js     # Конфигурация Webpack с Module Federation
│   │   └── package.json
│   ├── cards/
│   │   ├── src/
│   │   │   ├── components/       # UI-компоненты (например, Card, CardList)
│   │   │   ├── utils/            # Логика работы с API (api.js)
│   │   │   └── App.jsx           # Точка входа микрофронтенда Cards
│   │   ├── webpack.config.js     # Конфигурация Webpack с Module Federation
│   │   └── package.json
│   ├── profile/
│   │   ├── src/
│   │   │   ├── components/       # UI-компоненты (например, ProfileForm, AvatarUploader)
│   │   │   ├── utils/            # Логика работы с API (api.js)
│   │   │   └── App.jsx           # Точка входа микрофронтенда Profile
│   │   ├── webpack.config.js     # Конфигурация Webpack с Module Federation
│   │   └── package.json
│   └── host/
│       ├── src/
│       │   ├── components/       # Общие компоненты (например, Header, Footer)
│       │   ├── App.jsx           # Точка входа Host-приложения
│       │   └── routes/           # Настройка маршрутов для микрофронтендов
│       ├── webpack.config.js     # Конфигурация Webpack с Module Federation
│       └── package.json
```

### Уровень 3: Запуск Готового Кода

#### Операции для Запуска
Для запуска готового кода необходимо выполнить следующие шаги:
1. Проверить и установить node 20.18.1
```bash
 node -v
 npm -v
```
![NvmNodeNpmVersion.png](..%2Fimages%2FNvmNodeNpmVersion.png)

2. **Переход в директорию**  
   Сначала перейдите в директорию `frontend/microfrontend/host` с помощью команды:
    ```bash
    cd ./frontend/microfrontend/host
    ```
3. **Запуск всех микрофронтендов**  
   Запустите скрип `frontend/microfrontend/host` с помощью команды:
    ```bash
    npm run start:all
    ```
   или запустить из IntelliJ IDEA / WebStorm

   ![runMicrofrontend.png](..%2Fimages%2FrunMicrofrontend.png)

#### Удобный Запуск
Для более удобного и быстрого запуска вы можете использовать цепочку команд, объединив переход в директорию и запуск скрипта в одну строку:
```bash
cd ./frontend/microfrontend/host && npm run start:all
```
Эта команда сэкономит время, выполнив оба действия последовательно без необходимости вводить каждую команду отдельно.
